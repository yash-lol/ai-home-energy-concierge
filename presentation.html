The problem

Devices waste energy because none of them can see the whole picture

  • Your air conditioner does not know you left the house.
  • Your lights do not know the sun is out.
  • In San Diego, SDG&E charges 81% more per kWh between 4 PM and 9 PM — so when a load runs matters as much as whether.
A motion sensor sees an occupied room and concludes everything is fine — at noon, with the blinds open and every light on. No single device has enough context to be right.

What it does

Sense → reason → recommend → approve → act → confirm

The loop closes on real hardware, but a human authorises every physical action.

UNO Q senses→ hub fuses context→ 7 rules fire→ Python computes $→ LLM explains→ user approves→ the real lamp goes dark→ saving realized

It explains itself

Plain-language recommendations with a dollar figure, a kWh figure, and a carbon figure — every one of them traceable to a formula shown in the UI.

It acts physically

Approve on the phone and the UNO Q switches a real lamp — which reports its own draw falling 10.8 W → 0.0 W. The saving moves from avoidable to realized, and it is measured, not assumed.

It knows when to refuse

The comfort guardrail gates the actuator. Ask it to kill the A/C at 29 °C and it declines — with a reason.

The recommendation is impossible on any single device. "Your A/C is cooling an empty house" needs phone presence and room occupancy and load state and the tariff window — fused together, in one place.

Differentiator 1 of 3

Auditable AI — the model narrates, Python computes

The usual failure mode of an "AI saves you money" demo is a judge asking "where did that number come from?" and the answer being "the model said so."

The architectural rule

The LLM receives pre-computed values and may only phrase them. After every call, each numeric field is overwritten from the deterministic source. If the prose contradicts the computed figure, the figure wins.

Every estimate carries a formula string that the UI renders verbatim, so any number on screen can be recomputed by hand with a calculator.
  • All arithmetic lives in one 200-line module with no I/O and no LLM
  • Each wattage figure carries its own source (US DOE, ENERGY STAR)
  • Each finding carries the evidence that triggered its rule
  • Heuristics are labelled as heuristics in the UI, not hidden

Differentiator 2 of 3

The guardrail gates the actuator — not just the advice

Rule R7 is not advisory. It is enforced as a pre-flight check inside POST /api/apply, so the system will refuse to switch off the A/C when the room is above 27 °C — even when a user explicitly asks it to.
HTTP 409 — "Refused: living is 29.5 °C, above the 27 °C comfort limit — turning the A/C off would make the room uncomfortable."

R7 works at two independent layers: it removes findings from the recommendation list, and it blocks commands at the actuation boundary. Both are covered by the test suite.

Why this matters more than the actuation itself

Anything can switch a relay. A system that declines to carry out its own recommendation, and tells you why, is demonstrating judgment — and that is the precondition for ever trusting it to act unattended.

RuleDetects
R1lights on in a room empty > 10 min
R2HVAC running while the user is away
R3> 300 lux daylight, lights still on
R4A/C running with no temperature drop — likely an open window (heuristic, labelled)
R5phantom standby draw during a long absence
R6deferrable heavy load inside the 4–9 PM peak — charges only the rate delta
R7suppresses advice and refuses actuation above 27 °C / below 16 °C
R6 is worth a sentence on its own: running the dryer is legitimate — only its timing is wasteful. So it charges the rate difference, not the whole cycle.

The reasoning tier costs microseconds. All the latency that matters is LLM inference — which is precisely why it is the only part we accelerate on the NPU, and why the deterministic fallback is instant when the model is unavailable.
Edge filtering removes ~89% of broker traffic. The UNO Q samples at 1 Hz but publishes only on a material change (lux ±15%, temp ±0.3 °C, occupancy transition) or a 10 s heartbeat.
If the LLM endpoint is unreachable the benchmark reports that row as SKIPPED with the reason — it never substitutes the fallback's timing for the model's. Honest measurement over a flattering number.

Engineering & tooling

How it is built, and where we deviated on purpose

GenieX — the on-device LLM

OpenAI-compatible server on :18181. We chose the qairt runtime (AI Hub bundle, NPU-only, fastest) over llama_cpp (GGUF Q4_0, more flexible) because narration latency is the only latency that matters here.

QUAD — used for measurement

/quad-profile and /quad-orchestrate give authoritative NPU latency, power and utilization on real silicon. That is what QUAD is worth to this project.

On gap G6. QUAD's generate_code stage is blocked for UNO Q sensor/actuator GPIO codegen. We did not need it — the sketch, the MPU publisher and the actuator path are hand-written and tested. A pending platform gap did not become a project blocker, and we are not presenting mock output as if it ran.

Honest limitations

What we did not do, and what comes next

  • Load power is modelled, not metered. Published DOE and ENERGY STAR typicals, each carrying its source in the UI. A clamp meter or smart plug is the obvious next step.
  • Lux is not a calibrated measurement. It comes from the simulator, so we use it only against a coarse threshold — and every card names its source rather than implying a sensor we do not have.
  • R4 is a heuristic. We infer an open window from A/C runtime, a temperature stall and humidity. We do not sense the window, and the UI states that plainly.
  • Actuation is human-approved by design. Not a missing feature — a trust decision. R7 shows the machine refusing its own advice; that architecture is what would make autonomy safe later.
  • One room, one actuator. The topic contract is already per-room and per-load, so scaling is adding publishers — but we demo depth over breadth.

Next, in order

1 · Real metering on one circuit  ·  2 · QUAD NPU profile pasted beside the benchmark table  ·  3 · Multi-room fan-out  ·  4 · Opt-in autonomy for the loads R7 can prove are safe

The pattern generalises past energy: deterministic computation, a model that only explains, and a safety gate on the actuator is a reusable shape for any physical-AI system where being wrong has a cost.

Summary

Four devices producing one insight none of them could reach alone

1 · Placement of intelligence is the design

Rules at the edge in microseconds. A small model on the NPU for private, low-latency narration. A large model in the cloud for depth. Same problem, four tiers, each chosen against a latency and privacy budget.

2 · Auditable AI

The model narrates; Python computes. Every number on screen expands to the formula that produced it. Most LLM demos ask you to trust the number — this one lets you check it.

3 · Context fusion unlocks it

Phone presence and room occupancy and load state and the tariff window. No single device in this system could produce the recommendation.

4 · The loop closes, safely

Physical actuation, human-approved, with a comfort guardrail that can veto the machine's own advice — and does, on stage.
